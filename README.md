# 跨可用区存储卷绑定 / 供给控制器仿真

用 Go 仿真的 Kubernetes 风格集群存储子系统：三可用区集群、云盘（只能挂到同可用区节点）、
存储类（立即绑定 / 延迟绑定）、静态预建卷 + 动态供给、调度器与卷控制器协作（假定 / 撤销假定）、
多卷拓扑约束交集、副本可用区反亲和、卷扩容、节点删除重建。全部组件（节点、云盘供给接口、
调度器）均为内置仿真，由离散事件引擎驱动，一次实验在毫秒内跑完数百秒虚拟时间。

## 运行

```bash
go build -o storagesim .
./storagesim                 # 默认种子 5，终端打印对比表并启动控制台
./storagesim -seed 99        # 换随机种子
./storagesim -serve=false    # 只跑实验打印对比表，不启动 HTTP 控制台
```

控制台：http://localhost:8080 （`-addr` 可改端口）。页面包含：

- **实验对比**：立即绑定 vs 延迟绑定的全部验收指标
- **存储声明**：每个声明的绑定状态、所在可用区、绑定耗时
- **容器**：运行 / 卡住状态与卡住原因诊断
- **调度与绑定日志**：每次调度决策中的卷拓扑约束交集、配额感知选区、假定 / 撤销假定
- **节点与配额**：各节点处理器 / 内存水位、各可用区云盘配额使用
- **孤立盘检查**：云盘 ↔ 持久卷双向引用校验（必须为 0）、假定撤销后的回收记录

页面可输入种子重新运行实验，每 5 秒自动刷新。

## 仿真设定

- 3 个可用区：zone-a 最强、zone-c 最弱；云盘配额 650 / 550 / 350 Gi
- 12 个节点，分 compute / storage 两个节点池（Pod 有节点池亲和要求）
- 2 个存储类（cloud-ssd / cloud-hdd），均支持动态供给；8 个静态预建卷分布在不同可用区
- 33 个有状态服务陆续上线：多副本服务要求副本按可用区反亲和，30% 的 Pod 使用 2 个卷
- 云盘供给耗时 2~8s（8% 概率慢供给 16~36s），失败率 12%，配额在发起供给时预留
- t=100s 删除一个节点（Pod 重建，已绑定卷约束其回到原可用区）；t=160s 批量在线扩容

## 两种绑定模式

- **立即绑定（Immediate）**：声明创建后立刻在全部可用区里匹配空闲卷，匹配不到就在
  **随机可用区**动态供给 —— 盘落在哪里跟 Pod 会被调度到哪里完全脱节。
- **延迟绑定（WaitForFirstConsumer）**：声明保持未绑定，调度器挑选节点时把所有卷的
  拓扑约束取交集（已绑定卷的可用区、延迟卷的可满足可用区），与资源、节点池亲和、
  副本反亲和一起过滤；选定节点后对卷做**假定绑定**（预占静态卷或在该可用区发起供给），
  并优先选择云盘配额宽裕的可用区以保持配额均衡。供给失败 / 配额不足 / 假定超时 /
  节点删除都会**撤销假定**：释放预占卷、作废在途供给（完成即回收，不产生孤立盘）、
  释放节点资源，Pod 重新排队。

## 代码结构

| 文件 | 内容 |
| --- | --- |
| `sim.go` | 离散事件仿真引擎（虚拟时钟 + 事件堆） |
| `cloud.go` | 云盘供给接口仿真：分区配额、供给耗时、随机失败、扩容、删除 |
| `types.go` | 节点 / 存储类 / 声明 / 持久卷 / 云盘 / Pod 等类型与报告快照 |
| `cluster.go` | 绑定与供给控制器：立即绑定、动态供给、绑定、撤销假定、扩容、节点删除、孤立盘检查、卡住诊断 |
| `scheduler.go` | 调度器：卷拓扑约束交集、资源 / 节点池 / 反亲和过滤、配额感知选区、假定绑定 |
| `scenario.go` | 集群拓扑、工作负载生成、实验运行、指标统计、终端对比表 |
| `server.go` | HTTP API（`/api/report`、`/api/rerun`） |
| `web/index.html` | 控制台页面（内嵌于二进制） |
